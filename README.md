# ARGUS

> Take a drone. Strip the camera. You still need to see.

**ARGUS — Acoustic-Range Guided Ultrasonic System — is an experimental
acoustic sensing stack for reconstructing nearby 3D surface points from a
gimballed ultrasonic emitter and a four-microphone array.**

ARGUS combines timestamped tone-burst time-of-flight, cross-frequency phase
refinement, bistatic geometry, coherence rejection, and platform-motion
compensation. It is being developed as the acoustic perception layer for
[Echos](https://github.com/Hinedes/echos), an autonomous micro-UAV intended for
navigation in smoke, darkness, dust, and other zero-visibility environments.

> **Project status:** simulation research prototype. No physical ARGUS array
> has been built or validated yet. Reported accuracy values are synthetic-model
> results, not hardware specifications.

---

## Design motivation

I imagined gliding my hand along a wall. Continuous sensing — not a ping, a
conversation. Sonar is ill-suited for continuous ranging. Blasting the same tone
repeatedly compounds the problem — you get nulls, you get ambiguity, you get a
single number you can't trust.

I believe it's called SFCW. Stepped Frequency Continuous Wave. Turns out five
steps is the sweet spot. That's what ended up as Method C in the code. The
schedule is parameterised — the current five-tone configuration is a working
latency/information trade-off, not a global optimum.

**ARGUS** is the parametric array and everything that processes its returns.
The drone carrying it is **Echos**. Two names, one system.

## Signal chain

ARGUS currently models the following pipeline:

1. **Method C transmission.**  
   Frequency-agile finite tone segments are emitted back-to-back. The current
   reference uses five tones (40–48 kHz, 4 ms each, 2 ms guard). The receiver
   listens continuously and only drains outstanding returns after the final
   segment.

2. **Coarse absolute timing.**  
   A matched-filter onset estimate provides one time-unambiguous coarse ToF
   anchor per microphone (~4 µs resolution at 250 kHz).

3. **Cross-frequency phase refinement.**  
   For each microphone, all five tones are evaluated at the same coarse
   alignment (not five independent peaks). The differential phase slope across
   frequency refines inter-microphone delay below the ADC sample interval.

4. **Consistency validation.**  
   Cross-band agreement (low tones vs high tones must give the same TDOA),
   leave-one-tone-out stability (removing any one tone must not shift the
   slope), envelope compatibility (phase TDOA must stay near the coarse
   differential), and 3-of-4 microphone geometry checks (reconstructions must
   cluster). Any failure rejects the entire phase solution and falls back to
   the envelope.

5. **Bistatic reconstruction.**  
   Each microphone defines an ellipsoid:
   ```
   |P - E| + |P - M_i| = c t_i
   ```
   A damped nonlinear least-squares solver reconstructs the reflector point
   inside the known gimbal beam cone. The tilted diamond breaks the up/down
   symmetry a flat array would leave, giving signed vertical.

6. **Motion compensation.**  
   The outgoing path uses the emitter pose at emission time. The return path
   uses each microphone pose at its own reception time. This restores the
   static accuracy ceiling regardless of platform velocity.

## Current validated gates

| Gate | Current result | Scope |
| --- | --- | --- |
| Exact inversion | <1 µm error | Exact ToF generated by the same analytic model |
| Clean phase refinement | Sub-sample TDOA | Static, coherent, single-reflector synthetic waveforms |
| Near-coherent multipath | Conditional false-valid <5% | One delayed-copy multipath model |
| Full motion geometry | 0.14 cm at 2 m/s in reference run | Deterministic single reflector, exact poses |
| Echos trajectory contract | Loader and diagnostics implemented | Real Echos-generated replay still pending |
| Hardware | Not tested | No physical emitter or microphone array yet |

## Quickstart

ARGUS currently depends on NumPy. The test suite uses pytest.

```bash
git clone https://github.com/Hinedes/ARGUS.git
cd ARGUS

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

python -m pip install numpy pytest
python -m pytest -q
```

Validate an Echos trajectory export:

```bash
python -m argus.validate_echos_trajectory path/to/trajectory.npz
```

## Echos trajectory interface

ARGUS consumes `.npz` trajectory files following the echos-argus-trajectory v1
schema. Required arrays: body position, body quaternion (wxyz), linear and
angular velocities (body and world frames), gimbal pitch and quaternion, beam
axis, emitter position, all four microphone positions (world frame, at every
physics timestep). Metadata as embedded JSON.

Body frame: +X forward, +Y left, +Z up. Quaternion: active body-to-world,
order (w, x, y, z). Export at the full physics step rate; ARGUS interpolates
to arbitrary emission and reception times using linear interpolation
(position, beam axis) and SLERP (quaternions).

The current simulation geometry and the Echos physical layout are separately
defined — the acoustic validation uses a canonical tilted diamond while the
Echos interchange contract carries the exact physical microphone offsets.
These will be unified once end-to-end replay is operational.

The validation CLI runs five transform cross-checks against declared
tolerances:

| Check | Tolerance |
|---|---|
| Angular velocity transform (body → world) | 1e-8 rad/s |
| Gimbal quaternion composition | 1.0 deg |
| Beam axis from quaternion | 0.5 deg |
| Emitter position from body | 1.0 mm |
| Microphone positions from body | 1.0 mm |

## Current limitations

ARGUS has not yet been validated against physical acoustic hardware.

The current model does not yet include:

- a measured parametric-array transfer function;
- real transducer bandwidth, ring-down and leakage;
- rotor and structural noise recorded from an operating airframe;
- arbitrary multi-surface or diffuse multipath;
- material-dependent, spatially varying reflection phase;
- continuous Doppler/time-warp within each finite burst;
- measured temperature and humidity compensation;
- real Echos/Genesis trajectory replay through the acoustic chain;
- a physical gimbal model with inertia, lag and encoder noise;
- a common unified geometry model for the analytic and Echos physical arrays.

The current results establish software-model consistency and expose required
hardware tolerances. They do not establish field performance or survivor-safe
operating limits.
